---
title: The three agents
description: What Watcher, Planner, and Risk each do, and don't do.
---

## Watcher

**Reads.** Nothing else.

Listens for `flow_run` envelopes from the CLI peer. For each one it:

1. Looks up the Uniswap v3 NFT position by id using the connected wallet.
2. Reads the pool's current tick and liquidity through viem.
3. Builds a `PositionSnapshot`: pair, fee tier, range, current price,
   in/out of range flag, and range utilization.
4. Forwards `flow_propose` to the Planner peer with the snapshot.

The Watcher never proposes anything and never holds opinions. If the read
fails it emits `flow_run:error` and the flow stops.

## Planner

**Proposes.** Two candidates, never more.

Listens for `flow_propose` envelopes from the Watcher. For each one it:

1. Computes a recommended range using deterministic tick math,
   centred on the current tick and width derived from the current band.
2. Computes a tighter alternative: narrower band, higher fee capture,
   higher exit risk.
3. Forwards `flow_review` to the Risk peer with both candidates.

Numbers come from `packages/uniswap`, the LLM is not in this loop. If
you swap the model out, the proposed ranges do not change.

## Risk

**Critiques.** Picks a winner or defers.

Listens for `flow_review` envelopes from the Planner. For each one it:

1. Scores each candidate against deterministic checks: in-range coverage,
   distance from current tick, and buffer width.
2. Rejects the weaker candidate with a short reason.
3. Picks the highest-scoring survivor.
4. Emits `flow_run:done` back to the CLI peer with the chosen plan,
   the rejected alternatives, the reason string, and a confidence.

This is also the agent that names the plan before emitting the final envelope.
